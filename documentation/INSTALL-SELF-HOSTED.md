# Установка расширения в своей инфраструктуре

Инструкция для администратора организации. Сейчас расширение работает с Яндекс Телемостом; адрес сервиса анализа задаётся при сборке. Развёртывание backend во внутренней сети, авторизация и окончательный выбор модели ещё готовятся в задачах #31 и #29. До их завершения эту инструкцию можно использовать для локальной проверки и подготовки пакета расширения.

## Подготовить сервис анализа

Нужны Node.js 22 или новее, Chrome 120 или новее и экземпляр Ollama с установленной моделью, поддерживающей используемый формат ответа. Релизная модель пока не утверждена.

Текущий `server/index.ts` слушает только `127.0.0.1`; порт по умолчанию — `8787`. Для локальной проверки соберите сервис и запустите его рядом с Ollama:

```powershell
npm ci
npm run server:build
$env:ANALYSIS_MODEL = '<тег установленной модели>'
npm run server:start
```

Для доступа с других компьютеров нужен защищённый HTTPS-шлюз перед сервисом с аутентификацией и правилами доступа организации. Нынешний сервис не принимает внешние соединения напрямую и не выполняет аутентификацию клиентов. Не публикуйте его порт или порт Ollama в открытый интернет. Способ развёртывания шлюза и проверки доступа будет описан после выполнения #31.

## Собрать расширение для нужного адреса

В отдельном PowerShell укажите полный адрес обработчика `POST /v1/analyze`. Если шлюз добавляет префикс пути, адрес может выглядеть как `https://analysis.example.org/assistant/v1/analyze`. URL не должен содержать логин, пароль, параметры запроса или фрагмент. Для удалённого сервера требуется HTTPS; незашифрованный HTTP разрешён только для `localhost` и `127.0.0.1`.

```powershell
$env:ANALYSIS_API_URL = 'https://analysis.example.org/assistant/v1/analyze'
npm ci
npm run typecheck
npm run build
npm run check:package
```

Сборка помещается в `dist`. Скрипт записывает указанный URL в `background.js` и точное разрешение для его хоста в `dist/manifest.json`. Это настройка **пакета расширения**, а не переключатель в popup: при смене адреса нужно пересобрать `dist` и обновить установленное расширение. Не добавляйте в URL секреты: адрес входит в пакет.

Если `ANALYSIS_API_URL` не задан, используется локальный адрес `http://127.0.0.1:8787/v1/analyze`. Проверка пакета должна выполняться с тем же значением переменной, с которым выполнялась сборка. Версия в `manifest.json` и `package.json` должна совпадать.

## Установить в Chrome

1. Откройте `chrome://extensions`, включите режим разработчика и выберите «Загрузить распакованное расширение». Укажите папку `dist`.
2. После пересборки нажмите «Обновить» у расширения и обновите вкладку встречи Телемоста.
3. Откройте тестовую встречу, запустите занятие в popup и отправьте тестовое сообщение в чат. Для ручного запуска анализа используйте «Анализировать сейчас».
4. Проверьте успешный ответ сервиса и сообщение об ошибке при его недоступности. Локальный `npm run check:offline` проверяет контракт без модели, но не подтверждает работу установленного расширения.

Итоговый прогон на выбранной модели и в сети организации относится к #34. До него не считайте установку и качество анализа подтверждёнными для релиза.
