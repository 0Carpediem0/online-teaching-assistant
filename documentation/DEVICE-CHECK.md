# Автоматическая проверка перед занятием

## Исправление канала после исследования 12 ноября

Реальные соединения обнаружены в дочернем same-origin фрейме. В прежнем probe проверка event.source !== window отклоняла запрос родителя, а window.postMessage возвращал ответ самому дочернему окну. Теперь принимается запрос собственного или верхнего окна с проверкой origin, ответ направляется event.source. Это воспроизведено автоматическим тестом дочернего probe с родительским отправителем.

Выключенное устройство имеет отдельный результат off. Подробности скрыты под раскрытие. Состояние хранится в content script, поэтому закрытие popup не отменяет замер. Изменение DOM-состояния, replaceTrack, devicechange и возраст более 30 секунд помечают результат устаревшим. Отслеживание состояния имеет интервал 500 мс; произвольные изменения enabled/muted без изменения DOM не гарантированно обнаруживаются немедленно.

Источник клонированного capture track наследуется. Обработанный аудиотрек из исследования имеет неизвестное происхождение: автоматическое признание его микрофоном намеренно не реализовано. Нужен эксперимент с происхождением Web Audio output и одновременным звуком демонстрации. Выбранные устройства и надёжный селектор открытия настроек исследованиями не установлены, автоматического выбора/открытия нет.

После исправления прошли typecheck, production build и check-devices. Обновлённая установленная сборка на живой встрече пока не проверена. Полное покрытие таймаута, смены устройств и жизненного цикла popup браузерными тестами пока отсутствует.

Круглая кнопка в popup запускает один замер на 3–9 секунд. Во время замера нужно произнести фразу. Проверка необязательна, не запускается фоном и не мешает старту занятия. Результат и время остаются в памяти вкладки при закрытии popup.

После установки этой версии обновите расширение, затем страницу встречи и войдите заново: наблюдатель должен загрузиться до создания соединений Телемоста.

`device-probe.ts` работает в MAIN world с document_start. Он наблюдает создаваемые RTCPeerConnection и происхождение потоков getUserMedia/getDisplayMedia, не запрашивая собственный доступ. По кнопке читает getStats существующих исходящих senders: источник должен совпасть с trackIdentifier, счётчики bytesSent/framesEncoded должны расти; для микрофона нужен ненулевой audioLevel или прирост totalAudioEnergy. Потоки экрана исключаются. Неизвестные источники не дают успешного результата.

`devices.ts` собирает ограниченные результаты из доступных same-origin фреймов. MAIN world передаёт только логические признаки, без записей, идентификаторов устройств, адресов, SDP и текста чата. DOM-подписи выключенного микрофона/камеры из снимка 28 октября используются как дополнительный отрицательный сигнал, а не доказательство передачи.

Успех означает наличие сигнала/кадров и отправку в звонок во время проверки. Он не доказывает получение и воспроизведение у студентов, качество речи или правильность выбранного устройства. Тишина предлагает повторить с речью; неизвестный API/изолированный фрейм/обработанный источник без подтверждённого происхождения дают «недоступен для проверки». Камера и микрофон автоматически не включаются.

Проверки: `node scripts/check-devices.mjs`, `npm run typecheck`, `npm run build`. Автотест моделирует исходящую статистику, исключение экрана, проверку origin, отсутствие утечки deviceId, тишину и выключенное устройство. Реальная совместимость с текущим Телемостом требует прогона на встрече: звук+камера, mute, тишина, камера off, демонстрация экрана без камеры, закрытие popup во время замера. На момент реализации такой прогон не выполнен.
