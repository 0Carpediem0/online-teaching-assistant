# Первый замер качества анализа

22 ноября 2026 года выполнен один запрос `npm run quality:pilot` к `deepseek-flash` через backend проекта. Набор в `scripts/measure-analysis-quality.mjs` содержит 16 **синтетических** размеченных сообщений: 8 учебных вопросов, 5 технических проблем и 3 обычных реплики. Для каждой пары похожих сообщений вручную задана группа. Это проверка интеграции и начальное измерение, а не оценка качества на реальных занятиях.

| Показатель | Результат |
| --- | ---: |
| Валидный ответ API по контракту | 1 из 1 |
| Precision / recall / F1 для `question` | 1,00 / 1,00 / 1,00 |
| Precision / recall / F1 для `technical_issue` | 1,00 / 1,00 / 1,00 |
| Precision / recall / F1 для `other` | 1,00 / 1,00 / 1,00 |
| Неопределённые классификации | 0 |
| Пропущенные пары одинаковых вопросов или проблем | 0 из 6 |
| Ошибочно объединённые пары | 1 |
| Время полного запроса | 3741 мс |

Модель ошибочно объединила вопрос о знаке в третьем пункте (`sample-6`) и вопрос о значении в формуле (`sample-7`). Это разные учебные затруднения. Для пилота следует уточнить инструкцию модели: при сомнении оставлять вопросы раздельно. На повторном замере результат может отличаться; скрипт выводит номера ошибочных пар, поэтому промпт можно сравнивать на одинаковых данных.

Перед решением о выпуске нужен обезличенный корпус реальных сообщений и отдельный замер по нескольким занятиям: разговорные формулировки, опечатки, короткие реплики, ложные технические жалобы, сообщения не по теме, время ответа и ошибки JSON. Передавать реальные чаты в облачный API можно только после согласования с организацией.
