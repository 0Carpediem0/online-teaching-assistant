# Схема обработки данных

### Принятые правила для MVP

- Сбор сообщений начинается только после нажатия преподавателем кнопки «Начать занятие».
- Для временной шкалы используется время сообщения, показанное Телемостом. Время наблюдения браузером хранится отдельно как техническое поле.
- Сообщения группируются в пятиминутные интервалы. Пик вопросов определяется после классификации сообщений; до появления классификации можно показывать только пик сообщений.
- Автор сообщения в MVP не используется и не передаётся на анализ.
- Данные занятия хранятся в памяти вкладки. После закрытия или перезагрузки вкладки они теряются.
- Изменённое сообщение обновляется, пока оно не передано в анализ. После начала обработки отправленная версия фиксируется; правка не меняет уже отправленный пакет и его результат.

### Путь от страницы до интерфейса

```text
DOM Телемоста
  → адаптер извлекает текст и время сообщения
  → проверка и нормализация в событие расширения
  → локальная сессия и очередь сообщений
  → пакет JSON для анализа
  → ответ модели в JSON по согласованной схеме
  → проверка ответа и связывание с исходными сообщениями
  → расчёт пятиминутных пиков и обновление панели преподавателя
```

Адаптер — единственное место, которое знает селекторы DOM Телемоста. Остальные части работают с нормализованными событиями и не зависят от HTML страницы. DOM-узлы, разметка страницы и имя автора в пакет анализа не передаются.

### Событие сообщения

Внутри расширения каждое сообщение представляется объектом. JSON ниже показывает формат после нормализации; `platformTime.raw` сохраняет время ровно в том виде, в котором его показал Телемост. `minuteOfDay` вычисляется из этого значения и нужен для упорядочивания и подсчёта интервалов. Если время не удалось разобрать, `minuteOfDay` равен `null`, а сообщение можно показать без временной привязки.

```json
{
  "schemaVersion": "1.0",
  "eventId": "uuid-события",
  "sessionId": "uuid-занятия",
  "type": "chat.message",
  "revision": 1,
  "text": "Не слышно преподавателя",
  "platformTime": {
    "raw": "10:42",
    "minuteOfDay": 642
  },
  "observedAt": "2026-10-30T05:42:18.000Z",
  "processingStatus": "pending"
}
```

`eventId` связывает исходное сообщение, запрос и результат анализа. `revision` увеличивается при правке до отправки. `observedAt` — техническое время обнаружения браузером, оно не заменяет время Телемоста при показе занятия и расчёте временных пиков. Автор не включён в контракт.

Сборщик должен отделять новые сообщения от уже видимой истории чата. При старте занятия очередь очищается и фиксируется исходный снимок чата; сообщения из этого снимка не добавляются. В обработку попадают новые сообщения, появившиеся после снимка. Если панель чата открывается с задержкой, адаптер начинает отслеживание после её появления; этот промежуток может привести к пропуску сообщений и должен быть проверен на платформе.

Если одно и то же сообщение повторно отрисовано Телемостом, оно не должно повторно попадать в очередь. Для этого сборщик использует идентификатор строки DOM, пока он существует, и резервный отпечаток содержимого и времени для повторного сопоставления после перерисовки. Совпадающие по тексту и времени сообщения могут быть неоднозначны; расширение не должно склеивать их без достаточных оснований.

### Пакет на анализ

Перед отправкой пакет фиксируется: сообщения получают статус `in_flight`, их текст и версия больше не редактируются. Сообщения, ещё не отправленные в анализ, остаются редактируемыми. Каждая отправка имеет `analysisId`, поэтому результат можно сопоставить именно с теми версиями сообщений, которые получил анализатор.

```json
{
  "schemaVersion": "1.0",
  "analysisId": "uuid-анализа",
  "session": {
    "sessionId": "uuid-занятия",
    "startedAt": "2026-10-30T05:00:00.000Z",
    "timeZone": "Asia/Yekaterinburg"
  },
  "task": {
    "type": "classify_and_group_messages",
    "timeBucketMinutes": 5
  },
  "messages": [
    {
      "eventId": "uuid-события-1",
      "revision": 1,
      "text": "Не слышно преподавателя",
      "platformTime": "10:42"
    }
  ]
}
```

Это прикладной JSON-контракт между расширением и будущим анализатором. Целевой вариант размещения модели и требования к конфиденциальности описаны в [документе выбора модели](MODEL-SELECTION.md). Пакет отправляется без автора и только после старта занятия. Размер пакета и частота отправки уточняются при интеграции и проверке производительности.

### Ответ анализа

Ответ должен быть JSON, проверяемым по JSON Schema. Свободный текст ответа не используется как источник данных для интерфейса. Модель анализирует каждое сообщение, определяет, является ли оно вопросом или сообщением о технической проблеме, и компилирует похожие вопросы в общие формулировки. Для каждой такой формулировки модель возвращает ссылки на исходные сообщения. Так преподаватель видит сводный вопрос и при необходимости может перейти к конкретным репликам.

Модель также определяет темы и тип сообщений. Численное количество вопросов и пики по пятиминутным интервалам рассчитывает расширение по классификациям модели и времени Телемоста. Это оставляет подсчёт точным и проверяемым, а смысловую работу — распознавание и объединение вопросов — выполняет модель.

```json
{
  "schemaVersion": "1.0",
  "analysisId": "uuid-анализа",
  "messageResults": [
    {
      "eventId": "uuid-события-1",
      "revision": 1,
      "kind": "question",
      "topicId": "topic-homework",
      "confidence": 0.94
    }
  ],
  "compiledQuestions": [
    {
      "questionId": "question-homework",
      "text": "Как выполнять домашнее задание?",
      "eventIds": ["uuid-события-1", "uuid-события-2"],
      "topicId": "topic-homework"
    }
  ],
  "topics": [
    {
      "topicId": "topic-homework",
      "label": "Домашнее задание",
      "kind": "question",
      "eventIds": ["uuid-события-1", "uuid-события-2"]
    },
    {
      "topicId": "topic-audio",
      "label": "Проблемы со звуком",
      "kind": "technical_issue",
      "eventIds": ["uuid-события-3"]
    }
  ]
}
```

Допустимые значения `kind` на старте: `question`, `technical_issue`, `other`, `uncertain`. `confidence` — число от 0 до 1; при недостаточной уверенности результат помечается как `uncertain`, а не показывается как установленный факт. Схема ответа и перечень категорий являются проектным контрактом и уточняются при выборе модели.

### Представление в панели

Панель получает подготовленное состояние интерфейса, а не ответ модели напрямую. Для каждого сообщения она может показать текст и время Телемоста; для анализа — тип и тему. Сводные вопросы из `compiledQuestions` показываются один раз с количеством исходных сообщений и возможностью раскрыть эти сообщения. Пятиминутные интервалы отображаются как временные метки и число классифицированных вопросов. Интервал без распознанного времени не участвует в расчёте пиков, но само сообщение остаётся доступным для просмотра.

Пример агрегированного элемента интерфейса:

```json
{
  "from": "10:40",
  "to": "10:45",
  "questionCount": 8,
  "compiledQuestionCount": 3,
  "topicLabels": ["Домашнее задание", "Настройка среды"]
}
```

Сейчас в feature-ветке есть прототип адаптера и панели, но описанные JSON-контракты, фильтр стартового снимка, редактирование очереди, анализ, хранение результата и расчёт пиков ещё не реализованы.
